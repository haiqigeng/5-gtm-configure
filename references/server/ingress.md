## Classify the target

Confirm `server` from authoritative container metadata. Server containers expose Clients and Transformations and do not provide browser DOM,
history, click, form, dataLayer, Custom HTML, or Custom JavaScript execution semantics.

## Clients

Clients receive HTTP requests, claim a request class, transform it into one or more Event Data
events, and may package a response. Record Client type, priority, activation/claim criteria,
parameters, folder, and current fingerprint. Exactly one intended Client must claim each request
class. Reusing the default Google Analytics Client without changing claim behavior is routine;
changing priority or claim behavior is high impact.

Google documents that higher-priority Clients run first and the first match becomes active. Most
Google Analytics Client setups require no modification. A new Client requires a proved request-class ownership gap in the existing graph.

## Event Data

Server triggers and Event Data variables evaluate the event generated by the claiming Client. Name
the exact key path and prove it from current Client behavior/readback. Its server path is established independently of the web dataLayer source. One incoming request may generate more than one event;
record which event each downstream tag consumes.

## Server tags and templates

Use native server tags or an inspected sandboxed template. There is no browser Custom HTML/CJS
escape hatch. For community/vendor templates, record publisher, version, permissions, network
hosts, secret fields, automatic mapping, and upgrade authority. Unsupported template installation
or missing permissions are narrow blockers, not permission for an arbitrary HTTP implementation.

## Transformations

Transformations can allow, augment, or exclude event parameters before tags use them. They may
affect several tags, so inspect their scope and consumers recursively. Prefer destination-local
mapping for a local projection; use a Transformation only when shared governance or reuse warrants
its blast radius.

## Risk and authority

Routine authorized work can include isolated tags, triggers, Event Data variables, folders, and an
already installed compatible template. Require explicit high-impact authority for Client claim
changes, broad Transformations, template imports/upgrades/permission expansion, shared routing,
container settings, removal/replacement, or a live web endpoint cutover.
